# 客户指标可提供性 —— 审计报告（第二版）

- 审计对象：`data/customer_metric_mapping.json`（101 条判定）、`data/customer_metric_unsupported.csv`
- 数据基准：`data/tpops_all_metric.json`（TPOPS 指标字典 234 条）
- 客户需求基准：`高斯DB-指标明细（客户要求的应该要提供的指标明细）.xlsx` / `指标库`（101 行）
- 审计日期：2026-11-05
- **审计结论：可提供 74 条 / 无法提供 27 条**（第一版结论 32 / 69 **有误**，已修正）

---

## 0. 结论修正说明（重要）

第一版报告判定"32 可提供 / 69 无法提供"，**判定错误**。根因是**接口路径前缀用错**：

| | 正确 | 第一版误用 |
|---|---|---|
| 诊断优化章节接口 | `/rds/**gaussdb**/v3/instances/{id}/…` | `/rds/v3/instances/{id}/…` |

同一路径下少了 `gaussdb` 一段 → 20 个诊断优化接口**全部返回 404**，被误判为"平台未实现"。改用正确前缀后重新探测，20 个接口**全部存在**，其中 `top-sql-list`、`real-time-session`、`database-table-analysis`、`database-index-analysis`、`key-view-execute-node` 实测均返回 200。

**影响**：客户指标覆盖率从 32% 提升到 **73%**。上一版报告的第 3 节「平台只实现 6+1 个接口」结论**作废**。

### 2.1 「数据库诊断优化」章节 20 个接口 —— 全部实现

| 接口 | 方法 | 实测 | 能覆盖的客户指标 |
|---|---|---|---|
| `key-view-execute-node` | GET | 200（12 个节点） | 节点清单，调用其余接口的前置参数 |
| `real-time-session` | POST | 200 | 实时会话：state / query / query_runtime / trans_num / rollback_num / sql_num / database_name |
| `top-sql-list` | POST | 200，**返回真实 SQL 记录** | Top10 SQL、正在运行的 SQL、返回行数、扫描元组数 |
| `slow-sql-list` | POST | 400（参数未调通） | 慢查询总数、Select/DML 慢查询拆分 |
| `slow-sql-detail` | POST | 400（缺参数） | 慢 SQL 明细 |
| `slow-sql-execute-node` | POST | 200 | 慢 SQL 所在节点 |
| `database-table-analysis` | POST | 200 | **表级 8 项**：seq_scan / seq_tup_read / index_scan / index_tup_fetch / tuple_insert / tuple_update / tuple_delete / tuple_hot_update + vacuum/analyze 统计 |
| `database-index-analysis` | POST | 200 | 索引级：index_scan / index_tup_read / index_tup_fetch |
| `tables` / `schemas` / `databases` | GET | 200 / 400（缺 db_name / schema_name） | 表、模式、库清单 |

| `sql-patch` / `handle-sql-patch`（3 个） | GET/POST | 400（缺参数） | SQL Patch 管理（与指标无关） |
| `kill-session` / `kill-free-session` | POST | 500/400 | 终止会话（与指标无关） |

### 2.2 关键响应字段（决定可覆盖范围）

`database-table-analysis` 的响应字段是**客户表级指标的直接来源**：

```
db_name, schema, rel_name,
seq_scan, seq_tup_read, index_scan, index_tup_fetch,
tuple_insert, tuple_update, tuple_delete, tuple_hot_update,
last_vacuum, last_autovacuum, last_analyze, last_auto_analyze,
vacuum_count, autovacuum_count, analyze_count, auto_analyze_count
```

`real-time-session` 的响应字段覆盖**连接与会话类**客户指标：

```
session_id, pid, database_name, client_ip, user_name, wait, block_session,
wait_event, state, query_runtime, query, back_end_start, transaction_start,
query_start, application_name, exec_time, trans_num, rollback_num, sql_num
```

`top-sql-list` 的响应字段覆盖**SQL 维度**客户指标：

```
sql_id, user_name, sql_text, calls, calls_percent, cpu_percent, io_percent,
returned_rows, tuple_read, avg_elapse_time, total_elapse_time, min/max_elapse_time,
sql_hit_ratio, node_id, node_name, db_name
```

## 3. 仍然无法提供的 27 条

| 客户分类 | 条数 | 指标 | 原因 |
|---|---|---|---|
| **Bgwriter信息** | 8 | Buffers Alloc / Backend / Backend Fsync / Checkpoint / Clean、Checkpoint count(segments/timeout)、Max Written Clean | TPOPS 指标字典与诊断接口**均无 bgwriter 类指标** |
| **表信息**（live/dead tuple） | 3 | 已删除但未回收的行数（死亡行）、当前活跃的行数、死亡行占比 | `database-table-analysis` **没有 n_live_tup / n_dead_tup 字段**（只有 tuple_insert/update/delete/hot_update） |
| **事务信息**（live/dead tuple） | 3 | number of dead tuples、Garbage ratio、number of live tuples | 同上 |
| **基本信息**（静态配置） | 3 | 字符集、时区、页大小 | 平台无静态配置类指标；`/configurations` 未实现 |
| **连接情况** | 3 | 快路径函数调用的连接数、禁用的连接数、预提交事务数 | 会话接口无对应状态/字段 |
| **性能信息** | 3 | 临时文件大小、生成的临时文件数、数据库操作冲突次数 | 平台无临时文件/冲突计数指标 |
| **锁信息** | 1 | DB Num of accessexclusive locks | 平台锁只有大类（表级/行级/其他），无 accessexclusive 细分 |
| **可用性** | 1 | 服务端口{#PORT}检测 | `/rds/gaussdb/v3/instances/{id}/port` 404，未实现 |
| **基本信息** | 1 | 最大连接数 | 平台 `rds416` 是历史最高活跃会话数，不是配置上限；`/configurations` 未实现 |
| **Agent** | 1 | 发送设备名给Agent | Agent 侧行为，非监控指标 |

**共性**：27 条里有 **13 条是 pg_stat 静态/累计计数器（bgwriter 8 + live/dead tuple 5）**——TPOPS 的指标体系和诊断接口都没有对应字段；其余 14 条是配置项或平台侧未实现的接口。

## 4. 必须提请注意的四个风险

### 4.1 诊断优化接口是「即时查询」，不是时序指标

`POST /rds/v3/monitor/metrics` 返回时间序列，可直接按窗口推成时序；而 `real-time-session`、`top-sql-list`、`database-table-analysis` 返回的是**某一时刻的快照/明细**。要把它们变成客户要求的周期指标，采集进程必须**按周期反复调用并自行累计**（例如每 5 分钟拉一次表分析，把 tuple_insert 累加成速率）。这与指标接口的处理方式完全不同，架构上要分开。

### 4.2 当前实例是空库，表级/慢 SQL 类接口无数据可验

两个实例创建于 2026-11-03，实测：
- `top-sql-list` 有数据（仅系统自身的 `SELECT VERSION()` 等）
- `real-time-session` 返回 `sessions: []`
- `database-table-analysis` / `database-index-analysis` 返回 `total_count: 0`
- `databases` 返回空

即**接口可用但当前无业务数据**。表级 8 项指标、慢查询 3 项的**实际返回内容需要在有业务表的实例上复验**，不能只凭接口存在就判定可交付。

### 4.3 `slow-sql-list` 参数尚未调通

按文档必填 `start_time/end_time/instance_id/threshold/node_ids`（`threshold_unit` 可选）仍返回 400 `参数错误`，怀疑时间窗需与 WDR 快照分组对齐（文档写明 top-sql-list 的时间应取自 WDR 快照分组的 start_time/end_time）。**慢查询 3 项（总数 / Select / DML）目前是"接口存在但未验证"**，落地前需解决。

### 4.4 两处口径仍存疑（沿用第一版记录）

- 客户 `gaussdb.Blk_write_time` / `Blk_read_time` 是**数据库层累计耗时**，平台 `sys075`/`sys076` 是**磁盘单次平均耗时** —— 层级与口径都不同，当前仍按「近似对应」标注，需客户确认能否接受
- 客户「总连接数 / 后端进程数」映射到 `rds089`（CN连接数），但该指标在实例 `c35b8d07` 上无数据；会话接口可作为替代口径

## 5. 复现方式

```bash
# 重建映射表（与客户 Excel 逐行核对，对不上直接报错）
python tools/build_customer_metric_mapping.py

# 诊断优化接口：路径前缀是 /rds/gaussdb/v3/...（不是 /rds/v3/...）
curl -sk -X POST \
  https://172.16.103.193:8002/rds/gaussdb/v3/instances/<instance_id>/top-sql-list \
  -H "X-Mini-Token: <token>" -H "X-Language: zh-cn" -H "Content-Type: application/json" \
  -d '{"instance_id":"<id>","node_ids":["<node_id>"],"start_time":<ms>,"end_time":<ms>}'
```

> 每次探测都要用 mini-token 认证；勿频繁尝试错误口令，`login_failed_attempts` 累计会锁号。
