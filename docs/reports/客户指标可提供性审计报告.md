# 客户指标可提供性 —— 审计报告（第三版）

- 审计对象：`data/customer_metric_mapping.json`（101 条判定）、`data/customer_metric_unsupported.csv`
- 数据基准：`data/tpops_all_metric.json`（TPOPS 指标字典 234 条）
- 客户需求基准：`高斯DB-指标明细（客户要求的应该要提供的指标明细）.xlsx` / `指标库`（101 行）
- 审计日期：2026-11-05
- **审计结论：可提供 98 条 / 无法提供 3 条（覆盖率 97%）**

## 0. 结论修正过程（前两版均有误）

| 版本 | 可提供 | 无法提供 | 错在哪 |
|---|---|---|---|
| 第一版 | 32 | 69 | 只查了监控/告警接口，且**路径前缀漏了 `gaussdb` 一段** → 20 个诊断优化接口全 404，被误判为"平台未实现" |
| 第二版 | 74 | 27 | 修正前缀后拿到了诊断优化接口，但**只看了「监控大盘」和「数据库诊断优化」两章**，遗漏了「统一命令中心」 |
| **第三版** | **98** | **3** | 补查全部章节，发现命令中心可**执行任意 SQL**，直接覆盖 pg_stat 口径 |

关键教训：**「平台没有某指标」这种结论，必须以「该平台全部 API 都探测过」为前提**，否则就是把"没查到"当成"没有"。

## 2. 命令中心：可执行任意 SQL（本次突破点）

### 2.1 接口清单

| 接口 | 方法 | 实测 |
|---|---|---|
| `/gaussdb/v3/command-center/customer-commands` | GET | 200，**142 条内置命令**（SQL / SHELL / PYTHON） |
| `/gaussdb/v3/command-center/commands/{cmd_id}` | GET | 200，命令详情（含参数定义、约束、集群形态要求） |
| `/gaussdb/v3/command-center/customer-commands/{cmd_id}` | POST | 200，**执行单条命令**，返回 `job_id` + `node_tasks[].task_id` |
| `/gaussdb/v3/command-center/command/{cmd_id}/batch-exec-job/task-records` | GET | 200，轮询任务状态与错误信息 |
| `/gaussdb/v3/command-center/command/{cmd_id}/batch-exec-job/{job}/task-record/{task}/detail` | GET | 200，**任务输出结果**（`result` 为 JSON 数组） |

### 2.2 内置命令里已有现成的 pg_stat 查询

命令中心自带 140+ 条运维命令，其中多条正是客户要的指标：

| 命令 | 内容 |
|---|---|
| `general_single_sql_query` | **通用 SQL 查询**，模板 `select * from ({sql_text}) limit {limit};` —— 可执行任意 SQL |
| `dbs.full.get_stat_all_tables` | top 20 死元组占用（`n_dead_tup` / `n_live_tup` / `dead_tup_ratio`） |
| `query_slow_table_statistics` | 用户表 tuple 统计（`n_tup_ins/upd/del`、`n_live_tup`、`n_dead_tup`、`last_vacuum`…） |
| `query_table_statistics_info` | 指定表的统计信息 |
| `query_database_info` | **字符集**（`pg_encoding_to_char(encoding)`） |
| `DBS.FULL.get_database_size` | 各库大小 |
| `query_table_locks_ha` / `_distribute` | 表上锁（`pg_locks`） |
| `query_slow_sql_ha` / `_distribute`、`query_history_slow_sql_records` | 慢 SQL |

### 2.3 实测：一条 SQL 取回 27 类指标

用 `general_single_sql_query` 执行（返回 `status: succeed`，`result` 为 JSON 数组）：

```sql
select (select row_to_json(b) from pg_stat_bgwriter b) as bgwriter,
       (select string_agg(name||'='||setting,' | ' order by name) from pg_settings
         where name in ('max_connections','TimeZone','block_size','port','shared_buffers')) as settings,
       (select row_to_json(d) from pg_stat_database d where datname='postgres') as dbstat,
       (select count(*) from pg_locks where mode='AccessExclusiveLock') as accessexclusive_locks,
       (select count(*) from pg_prepared_xacts) as prepared_xacts,
       (select string_agg(datname||':'||pg_encoding_to_char(encoding),',') from pg_database) as encodings
```

## 3. 仍然无法提供的 3 条

| 客户指标 | 原因 |
|---|---|
| `gaussdb.Fastpath_function_call`（快路径函数调用的连接数） | PG 侧**没有 fastpath 计数器**；`pg_settings` 只有 `gsi_fastpath_level`（strict/…）开关，不是计数 |
| `gaussdb.Disabled_conn`（禁用的连接数） | PG **没有「禁用连接」概念**；`pg_settings` 只有 `extip_reserved_connections=5` / `service_reserved_connections=10` / `sysadmin_reserved_connections=3`（预留而非禁用） |
| `gaussdb.sendAgentName`（发送设备名给Agent） | Agent 侧行为，数据库内无对应可查询对象 |

其余 98 条全部可提供，匹配程度：**直接对应 79、近似对应 10、需换算 6、可统计 3**。

「需换算 6」指客户要**每秒速率**、而 `pg_stat_database` 给的是**累计计数**（`xact_commit` / `tup_inserted` / `tup_updated` / `tup_deleted` / `tup_returned` / `tup_fetched`），需由采集侧按周期差分。

「近似对应 10」指口径基本一致但不完全等同：服务可用性检测（实例状态 / health-status）、服务端口检测（只能取端口号，探测需另走 `/rds/health-status`）、连接使用率、连接数使用率、DB 锁信息（按库聚合）、Standby/Primary 状态（DN 主备状态）、启动时间/运行时长（CN 进程启动时刻）、GAUSSDB服务状态/数据库状态。

## 4. 落地时的四个风险

### 4.1 命令中心是「任务派发 + 轮询」，不是同步查询

一次调用要经过：下发命令 → 拿 `job_id` → 轮询 `task-records` → 取 `detail.result`，实测单次往返 **约 10–20 秒**。因此采集进程应：

- **合并成少量几条 SQL**（像 2.3 那样一条 SQL 取回多类指标），而不是每个指标一次命令
- 每轮询周期对每个实例的每个 CN 节点下发一次，轮询取结果
- 速率类指标自己缓存上一轮累计值做差分

### 4.2 累计计数与时间序列混用

`pg_stat_*` 是累计量（`stats_reset` 起算），而 `POST /rds/v3/monitor/metrics` 是真正的时序。Kafka 侧要统一成客户的"每秒/每分钟"口径，得在采集侧统一做差分，并处理实例重启导致的计数归零。

### 4.3 当前实例是空库

两个实例创建于 2026-11-03：`pg_stat_user_tables` 无业务表、`real-time-session` 空、`databases` 空（仅系统库）。**表级 22 项指标虽有字段，但当前实例上没有真实数据可验**，需在有业务数据的实例上复验数值合理性。

### 4.4 命令执行本身有风控约束

命令详情里明确写着："执行自定义命令（来源非系统默认）属于风险操作"，并要求确认不会产生慢SQL、输出大小可控（建议每轮一条合并 SQL、`limit` 适中）。另有约束字段 `constraint_config`：执行节点角色/组件类型须满足（如 `general_single_sql_query` 要求 `limit_node_types=[master]`、`limit_component_types=[cn,dn]`）、集群形态须匹配。

另注：任务记录里 `sql_text` 属敏感参数，会被掩码显示为 `******`（执行本身不受影响）。

## 5. 复现方式

```bash
# 重建映射表（与客户 Excel 逐行核对，对不上直接报错）
python tools/build_customer_metric_mapping.py

# 命令中心：列出内置命令
curl -sk https://172.16.103.193:8002/rds/gaussdb/v3/command-center/customer-commands \
  -H "X-Mini-Token: <token>" -H "X-Language: zh-cn"

# 命令中心：执行 SQL（cmd_id = general_single_sql_query 的 73722acc-bff6-4d04-adc0-bc1e1fa1eb7d）
curl -sk -X POST \
  https://172.16.103.193:8002/rds/gaussdb/v3/command-center/customer-commands/73722acc-bff6-4d04-adc0-bc1e1fa1eb7d \
  -H "X-Mini-Token: <token>" -H "Content-Type: application/json" \
  -d '{"instance_id":"<iid>","node_ids":["<node_id>"],
       "params":[{"param_name":"sql_text","param_value":"select 1 as x"},
                  {"param_name":"limit","param_value":"10"}]}'
# → 返回 job_id / task_id，再查 task-records 状态与 task-record/{id}/detail 取结果
```

> 每次探测都要用 mini-token 认证；勿频繁尝试错误口令，`login_failed_attempts` 累计会锁号。
