# 不可提供指标清单（客户交付版）

客户指标库共 101 个指标，其中 **98 个可提供**（口径见《交付-指标口径说明.md》），**3 个无法提供**。本文档逐条说明：客户要什么、我们为什么给不了、能不能变通。

> - 数据来源：`tpops_kafka_collector/mapping/data/metric_rules.json`（`enabled = false` 的 3 条规则，每条自带 `unsupported_reason`）
> - 生成方式：`python tools/build_delivery_docs.py`（表驱动，重跑输出不变）

## 1. 处置方式

- 这 3 个指标**不会出现在 Kafka 消息里**。
- 采集端每轮遇到它们时**丢弃并计数**：`dropped_unsupported` 计数 = **3**（每轮固定 3），日志里记录被丢弃的指标名。
- 计数会随每轮的采集报告一起上报，可用于核对「本轮应投指标数」与「实投指标数」的差。

## 3. 逐条说明

### 3.1 快路径函数调用的连接数（gaussdb.Fastpath_function_call）

| 项 | 内容 |
|---|---|
| 客户指标英文名 | `gaussdb.Fastpath_function_call` |
| 中文名 | 快路径函数调用的连接数 |
| 指标分类 | 连接情况 |
| 数据类型 / 单位 | 整数 / 个 |
| 采集周期 | 1 分钟 |

**客户要什么**：快路径函数调用的连接数

**为什么给不了**：PG 侧无 fastpath 计数器；pg_settings 仅有 gsi_fastpath_level 开关

**能不能变通**：**可以做近似，但口径不等价。**若客户要的是「当前有多少连接正在走快路径调用内置函数」，可在命令中心里对 `pg_stat_activity` 做一次附加统计（`state = 'active'` 且 `query` 命中内置函数名白名单）来近似。注意两点：一是这是**瞬时快照**的连接数，不是「累计快路径调用次数」；二是白名单需要客户给出他们关心的内置函数清单。若客户其实想要的是「快路径开关状态」，那是一条配置项（`pg_settings.gsi_fastpath_level`），可以单独作为一条状态类指标提供。

### 3.2 禁用的连接数（gaussdb.Disabled_conn）

| 项 | 内容 |
|---|---|
| 客户指标英文名 | `gaussdb.Disabled_conn` |
| 中文名 | 禁用的连接数 |
| 指标分类 | 连接情况 |
| 数据类型 / 单位 | 整数 / 个 |
| 采集周期 | 1 分钟 |

**客户要什么**：禁用的连接数

**为什么给不了**：PG 无「禁用连接」概念；pg_settings 仅有 reserved_connections 等预留连接

**能不能变通**：**不能直接给出，但可以按容量口径换算。**客户指标库里「禁用的连接数」的常见业务含义是「因为连接策略 / 预留策略而无法被使用的连接数」。若客户确认是这个含义，可以换算为 `max_connections - numbackends - reserved_connections`（可建立总量 - 已建立 - 预留），这是一条**容量差值**，和「被禁用的连接」不是同一个东西，口径需要客户书面确认后才提供。若客户指的是「连接被拒绝的次数」，平台侧没有对应计数器，同样无法提供。

### 3.3 发送设备名给Agent（gaussdb.sendAgentName）

| 项 | 内容 |
|---|---|
| 客户指标英文名 | `gaussdb.sendAgentName` |
| 中文名 | 发送设备名给Agent |
| 指标分类 | Agent |
| 数据类型 / 单位 | 文本 / - |
| 采集周期 | 5 分钟 |

**客户要什么**：发送设备名给Agent

**为什么给不了**：Agent 侧行为，不是数据库可查询的监控指标

**能不能变通**：**无法从数据库侧提供，应由采集 Agent 侧承担。**这条不是数据库的监控指标，而是「把设备名发给 Agent」这个 Agent 行为本身。可行的做法有两个：一是让部署侧的 Agent 在上报心跳时直接带上主机名；二是由采集端把节点清单里的节点名 / 主机名放进 `tags`（`tags.node_id`、`tags.instance_name` 已有），供客户侧自行关联 —— 但这属于「顺带带上」，不能算作一条指标。若客户必须要这条指标，需要在 Agent 侧新增一个采集点。

## 4. 如果客户坚持要这 3 条

1. 请客户先书面确认每条指标的**业务定义**（尤其是「禁用连接」到底指什么）。
2. 我们按上面的「变通」口径给出**替代指标**（新指标名 + 取数方式 + 口径说明），由客户决定是否接受替代。
3. 如果客户接受替代口径，我们会**新增指标**而不是改这 3 条的英文名 —— 客户指标库里的英文名以《交付-客户指标英文名核对清单.md》核对完的为准。
