# GaussDB 指标与告警采集端 —— 部署运行说明

面向**客户侧运维人员**。

采集端是**常驻进程**：按周期从 TPOPS（GaussDB 监控平台）拉取指标与告警 →
按 ITSCADA 字段规范转成 JSON → 投递 Kafka（PLAINTEXT）。**投递成功才推进水位**；
投递失败不推进，重启后从水位续传（至少一次语义）。

---

## 1. 前置条件

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Linux（x86_64 / aarch64） | 已在 CentOS / Ubuntu 验证；麒麟 V10 SP2+ 可用（见下） |
| Python | **3.7 ~ 3.11** | **3.12+ 不行**（`kafka-python 2.0.2` 与之不兼容）。麒麟 V10 SP2/SP3 自带 3.7.9，直接用系统的；V10 SP1 自带 3.6.8，**需先升级** |
| 依赖 | `requests` / `kafka-python` / `urllib3` | 随部署包提供，**离线安装**；目标机无需 conda、无需编译、安装过程不联网 |
| Kafka | 可连的 broker（PLAINTEXT） | **需客户预先建好**两个 Topic：指标 / 告警。采集端**不创建 Topic** |
| TPOPS 平台 | 平台地址 + 有权限的账号 | 账号需能访问：实例列表、监控指标、告警记录、命令中心、诊断优化 |
| 平台证书 | 平台为自签证书 | 默认**不校验**（`TPOPS_VERIFY_TLS=false`）；要校验需自行导入证书后置 `true` |
| 磁盘 | 状态目录可写 | 不可写 → 重启后水位丢失，数据整段重投 |
| 出站网络 | 采集端 → TPOPS（https）、采集端 → Kafka | 两个方向都要通 |
| 安装权限 | 能在 `/opt` 建目录 | 采集端只写自己的安装目录，不改系统 Python |

## 2. 部署

### 2.1 交付物

`tpops_metric_collector_<版本>.tar.gz`（`.sha256` 校验文件**单独传**）：

```
tpops_metric_collector_<版本>/
├── collector.sh          # 部署与运维脚本（一个脚本，位置参数选功能）
├── tpops_kafka_collector/ # 采集端程序（含映射数据）
├── wheels/               # 离线依赖包（含引导用的 pip wheel）
├── .env.example          # 环境变量样例
├── 部署运行说明.md / 软件部署指南.pdf
└── MANIFEST.txt          # 逐文件 sha256
```

`collector.sh` 是 **bash 脚本**，请用 `bash collector.sh <命令>` 运行
（用 `sh` 调用也能跑 —— 脚本会自动改用 bash 重跑）。

用法：

| 命令 | 作用 |
|---|---|
| `check-env` | 环境预检（只读，不装任何东西） |
| `check-deps` | 离线依赖预检（真装一遍到临时目录再删） |
| `install` | 安装：装依赖 + 部署采集端包 |
| `verify` | 部署后自检 |
| `run` | 启动采集端 |

### 2.2 部署步骤

```bash
# ── 第 0 步：验校验和 + 解压 ──
sha256sum -c tpops_metric_collector_<版本>.tar.gz.sha256     # 期望：OK
tar xzf tpops_metric_collector_<版本>.tar.gz
cd tpops_metric_collector_<版本>

# ── 第 1 步：检查环境（只读）──
bash collector.sh check-env
#   有 [FAIL] 项先别往下走。装到别的目录：bash collector.sh check-env /data/tpops-collector

# ── 第 2 步：离线依赖预检 ──
bash collector.sh check-deps

# ── 第 3 步：安装 ──
sudo bash collector.sh install
#   装到别的目录：sudo bash collector.sh install /data/tpops-collector
#   目标机没有 venv 模块时：sudo INSTALL_MODE=vendor bash collector.sh install

# ── 第 4 步：配置 → 自检 → 启动 ──
sudo vi /opt/tpops-collector/.env          # 30 项清单见 §3
sudo chmod 600 /opt/tpops-collector/.env   # 文件里有口令
sudo bash /opt/tpops-collector/collector.sh verify
cd /opt/tpops-collector
bash collector.sh run
```

`install` 做两件事：**阶段一**在安装目录内建独立环境并离线装好运行时依赖
（不碰系统 Python）；**阶段二**把采集端程序与配套文件放进安装目录。
全程只写安装目录内部。

> 部署包里的 `.env.example` 中 `TPOPS_USER` / `TPOPS_BASE_URL` 是占位符
> `CHANGE_ME`，**必须改成客户自己的账号与平台地址**。
>
> 只填必填项也能跑 —— 必填项只有 `TPOPS_USER`、`TPOPS_PASSWORD`、
> `KAFKA_BOOTSTRAP_SERVERS` 三项，其余取默认值。

### 2.3 systemd 单元（参考）

```ini
[Unit]
Description=GaussDB TPOPS Kafka Collector
After=network-online.target

[Service]
Type=simple
User=tpops
WorkingDirectory=/opt/tpops-collector
EnvironmentFile=/opt/tpops-collector/.env
# 水位目录交给 systemd 建 —— 属主自动是服务用户，
# 不会出现「root 建的目录、服务用户写不进去」导致水位静默丢失
StateDirectory=tpops
StateDirectoryMode=0750
Environment=STATE_DIR=/var/lib/tpops
ExecStart=/opt/tpops-collector/collector.sh run
Restart=always
RestartSec=10
# 停机要给足时间：收尾（等在途请求 + 落水位 + flush Kafka）最长 30 秒
KillSignal=SIGTERM
TimeoutStopSec=45

[Install]
WantedBy=multi-user.target
```

## 3. 环境变量

全部配置**只从环境变量读取**，启动时一次性加载，运行期间不再读。
必填项缺失或取值非法 → **启动即失败**（不发任何请求），退出码 **2**。

### 3.1 TPOPS 平台

| 变量名 | 默认值 | 必填 | 说明 | 改错的后果 |
|---|---|---|---|---|
| `TPOPS_USER` | — | **是** | 平台登录用户名 | 缺失 → 退出码 2；用户名错 → 认证失败，可能锁号 |
| `TPOPS_PASSWORD` | — | **是** | 平台登录口令 | 缺失 → 退出码 2。口令只走环境变量，不写日志 |
| `TPOPS_BASE_URL` | `https://172.16.103.193:8002` | 否 | 平台地址（含端口） | 连不上 → 所有通道失败 |
| `TPOPS_VERIFY_TLS` | `false` | 否 | 是否校验平台证书 | 平台是自签证书；置 `true` → TLS 握手失败 |
| `TPOPS_REQUEST_TIMEOUT` | `60` | 否 | 单请求超时（秒），≥ 1 | 过小 → 慢响应被当超时；过大 → 平台卡死时长时间挂住 |
| `TPOPS_AUTH_FAILURE_COOLDOWN_SECONDS` | `60` | 否 | 认证失败后的静默期（秒），≥ 0；`0` = 关闭 | 平台认证失败会累计并**锁号**；静默期过小仍会撞锁号，过大则改完口令要等很久 |

### 3.2 Kafka

| 变量名 | 默认值 | 必填 | 说明 | 改错的后果 |
|---|---|---|---|---|
| `KAFKA_BOOTSTRAP_SERVERS` | — | **是** | broker 地址，逗号分隔；PLAINTEXT | 缺失 → 退出码 2；地址错 → 投递全失败（不推进水位，持续重投） |
| `KAFKA_TOPIC_METRICS` | `gaussdb.metrics` | 否 | 指标消息 Topic | 与客户订阅不一致 → 客户看不到指标 |
| `KAFKA_TOPIC_ALARMS` | `gaussdb.alarms` | 否 | 告警消息 Topic | 同上 → 客户收不到告警 |
| `KAFKA_TOPIC_PARTITIONS` | `4` | 否 | Topic 分区数，≥ 1 | **当前未生效** —— 采集端不创建 Topic、不校验分区数 |
| `KAFKA_COMPRESSION` | `gzip` | 否 | 压缩算法，只允许 `none` / `gzip` | 取值非法 → 退出码 2。lz4/snappy/zstd 需额外装带 C 扩展的 Python 包，目标机通常没装 |

### 3.3 调度与指标窗口

| 变量名 | 默认值 | 必填 | 说明 | 改错的后果 |
|---|---|---|---|---|
| `POLL_INTERVAL_SECONDS` | `30` | 否 | 调度 tick 粒度（秒），≥ 1 | **不是采集周期** —— 各通道按自身档位到期执行。调大只是主循环变慢，但大于某通道周期时该通道会被拉长到整数倍 |
| `METRIC_WINDOW_HOURS` | `2` | 否 | 指标查询窗口（小时），≥ 1 | **不得小于 1** —— 小于 1 覆盖不到 3600s 周期的指标，该指标大面积 null |
| `METRIC_END_LAG_MINUTES` | `5` | 否 | `end_time` 回退量（分钟），≥ 0 | 平台入库滞后约 5 分钟，不回退 → 尾部大量 null；过大 → 数据偏旧 |

### 3.4 命令中心（SQL 通道）

| 变量名 | 默认值 | 必填 | 说明 | 改错的后果 |
|---|---|---|---|---|
| `CMD_CONCURRENCY` | `2` | 否 | 并发下发命令数，1~10 | 调大 → 平台加压、易触发限流整轮失败；超 10 → 退出码 2 |
| `CMD_LIMIT` | `1000` | 否 | 单条命令 limit 行数，1~1000 | **当前未生效** |
| `CMD_PAGE_SIZE` | `100` | 否 | 合并 SQL 分页容量，1~1000 | 平台单次输出上限 102400 B，超了**整条任务失败**（非截断）；调大易触顶 |
| `CMD_POLL_TIMEOUT` | `60` | 否 | 命令任务轮询超时（秒），≥ 1 | 单次往返实测 3~8 秒；过小 → 误判超时并重试 |
| `CMD_RETRY_ATTEMPTS` | `3` | 否 | 单条命令重试次数，≥ 0 | 实测偶发失败约 3/50；置 `0` → 偶发失败直接丢数据 |

### 3.5 告警

| 变量名 | 默认值 | 必填 | 说明 | 改错的后果 |
|---|---|---|---|---|
| `ALARM_LIMIT` | `100` | 否 | 告警接口单页条数，1~100 | 超 100 → 退出码 2；不翻页 → 靠水位续传补 |
| `ALARM_RETENTION_DAYS` | `30` | 否 | 平台历史告警保留窗口（天），≥ 1 | 平台只保留 30 天；超出时采集端会显式告警（补不回来） |

### 3.6 慢 SQL 脱敏

| 变量名 | 默认值 | 必填 | 说明 | 改错的后果 |
|---|---|---|---|---|
| `SQL_MASKING_ENABLED` | `true` | 否 | 是否对慢 SQL 文本脱敏 | 关闭后 SQL 原文外发 —— **需客户书面确认**才能关 |
| `SQL_TEXT_MAX_LENGTH` | `512` | 否 | 慢 SQL 文本最大长度（字符），≥ 1；超出截断并标记 | 过大 → 消息体膨胀；过小 → 失去排障价值 |

### 3.7 通用重试

| 变量名 | 默认值 | 必填 | 说明 | 改错的后果 |
|---|---|---|---|---|
| `RETRY_MAX_ATTEMPTS` | `5` | 否 | 通用重试最大尝试次数，≥ 0 | **当前未生效**（各调用点用各自的配置） |
| `RETRY_BASE_SECONDS` | `1.0` | 否 | 退避基数（秒），≥ 0；指数退避 1→2→4→8 | 命令中心重试的退避基数取自这里；过大拖慢恢复，过小则连续打在故障平台 |

### 3.8 运行时

| 变量名 | 默认值 | 必填 | 说明 | 改错的后果 |
|---|---|---|---|---|
| `STATE_DIR` | `./state` | 否 | 状态目录（相对当前工作目录） | 不可写 → 每轮落盘失败，水位与去重状态全丢（数据整段重投） |
| `HEALTH_HOST` | `127.0.0.1` | 否 | 健康端点监听地址 | 改成 `0.0.0.0` 会把端点暴露到网络上 |
| `HEALTH_PORT` | `8088` | 否 | 健康端点端口，1~65535 | 被占用 → 装配失败，退出码 **3** |
| `LOG_LEVEL` | `INFO` | 否 | `DEBUG/INFO/WARNING/ERROR/CRITICAL` | 取值非法 → 退出码 2；`DEBUG` → 日志量大增 |
| `LOG_FORMAT` | `text` | 否 | `text`（人读）或 `json`（给日志平台按字段取） | 取值非法 → 退出码 2 |

## 4. 启动与优雅退出

### 4.1 启动

```bash
bash /opt/tpops-collector/collector.sh run
```

> `run` 会**自动读取安装目录下的 `.env`**（只解析 `KEY=VALUE`，不执行文件内容）。
> 采集端只从进程环境读配置 —— 不加载的话会报「缺少必填环境变量：TPOPS_USER」。
> 用 systemd 时由 `EnvironmentFile=` 提供，效果相同。
> 若要手工直接跑 `python -m tpops_kafka_collector.main`（不经 `run`），需自己加载：
> `set -a && source .env && set +a`。

启动期依次完成：加载并校验配置 → 从状态目录恢复水位 / 差分基线 / 幂等键 →
平台画像（发现一次后固化）→ 装配 Kafka 生产者、五个采集器、调度器、健康端点。

**TPOPS 认证是惰性的** —— 首次真正发请求时才认证。

**退出码**：

| 退出码 | 含义 |
|---|---|
| `0` | 正常退出（收到 SIGTERM / SIGINT 后优雅退出） |
| `2` | 配置缺失或非法（必填项没填、数值越界、枚举取值非法） |
| `3` | 装配失败（如健康端点端口被占用） |

### 4.2 优雅退出

收到 **SIGTERM**（`systemctl stop`）或 **SIGINT**（Ctrl-C）后：

```
停止发起新的 HTTP 请求 → 在途请求最多等 30 秒（超时即放弃）
  → 原子写水位 → flush / 关闭 Kafka producer → 退出码 0
```

- 停机后**不再发起新的 HTTP 请求**，进程不会被一个挂死的请求拖住。
- 水位**每轮结束就落盘**（不只在退出时落盘），崩溃最多丢一轮。
- `kill -9`（SIGKILL）**不执行收尾** —— 水位可能丢一轮，重启后那一轮会被重投
  （客户侧按幂等键去重，不会产生重复数据）。

## 5. 运行期文件

全部在 `STATE_DIR`（默认 `./state`）下：

| 文件 | 内容 | 运维须知 |
|---|---|---|
| `watermark.json` | 水位、差分基线、已投递的幂等键集合 | **自动维护，不要手改**。删除它 = 清空去重状态 = 下一轮整段重投 |
| `platform_profile.json` | 平台画像：采集哪些实例、`mode`、引擎版本、master 节点数 | **可手工编辑** —— 换实例 / 加实例 / 删实例都改这里，改完下次启动生效。平台新增实例**不会**自动加入（日志会提示需人工更新；删掉该文件重启可重新发现） |

每次启动会拿画像与平台现状对一遍，**只记日志、不改文件**：实例在平台上已不存在
→ ERROR（人工确认）；平台上有画像没记录的实例 / 引擎名变了 / master 数变了
→ WARNING（需人工确认）。

## 6. 健康检查

| 端点 | 语义 | 响应 |
|---|---|---|
| `GET /healthz` | **存活** —— 进程能应答就是 200，**不看任何依赖** | `200` + `{"status":"ok","check":"liveness",...}` |
| `GET /readyz` | **就绪** —— 依赖不可用时返回 **503** | `200` / `503` + 依赖明细（不含任何凭据） |

`/readyz` 返回 503 的两种情况：TPOPS 未完成认证 / 最近一次成功采集距今超过 180 秒。

> 两个端点语义必须分开 —— 编排器若把 liveness 挂在依赖上，一次 Kafka 抖动就会
> 反复重启采集端，重启又让水位重放。

```bash
curl -s http://127.0.0.1:8088/healthz
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8088/readyz   # 期望 200
```

> 默认只监听回环。要给编排器探针用需改 `HEALTH_HOST` —— 改了即暴露到网络。

## 7. 日志

- 输出到 **stderr**（日志轮转由运维负责，采集端不自己写文件）。
- `LOG_LEVEL` 默认 `INFO`；`LOG_FORMAT` 默认 `text`：
  - `text`：`2026-11-24 10:00:00,123 | INFO | tpops_kafka_collector.scheduler | ...`
  - `json`：每行一个 JSON 对象，轮询汇总行摊平成顶层字段，日志平台可直接按字段取。
- 第三方库（`kafka` / `urllib3` / `requests` 等）已降噪到 `WARNING`。
- **口令、mini-token、业务 SQL 文本都不进日志**。

## 8. 排障

| 症状 | 可能原因 | 处理 |
|---|---|---|
| `sha256sum -c` 报 `FAILED` | 压缩包传输中被改动或损坏 | 重新传。**校验文件要与压缩包分开传** |
| `sh collector.sh ...` 报 `syntax error near unexpected token '<'` | 用了 `sh` 调用（本脚本是 bash 脚本，`sh` 在麒麟上通常是 dash，不支持进程替换语法） | 改用 `bash collector.sh <命令>`；或直接 `./collector.sh <命令>`（脚本自带可执行位与 bash shebang） |
| `check-env` 报 `[FAIL] 没有可用的 Python` | 目标机只有 3.6（麒麟 V10 SP1 自带 3.6.8）或没有 Python | 升级到麒麟 V10 SP2+（自带 3.7.9），或提供 3.7~3.11 的解释器 |
| `check-env` 报 `[FAIL] 找到但太新：3.12.x` | 目标机上最低的可用 Python 是 3.12+ | 换用 3.7~3.11 的解释器。3.12+ 上 `import kafka` 会失败，不是配置问题 |
| `check-env` 报 `[FAIL] 没有 venv 模块` | 目标机裁掉了 venv | 装 `python3-venv`；或改用 `sudo INSTALL_MODE=vendor bash collector.sh install` |
| `check-env` 报 `[FAIL] 父目录不可写` | 安装目录的父目录当前用户写不了 | 用 `sudo` 跑 `collector.sh install`，或换个目录 |
| `check-deps` 报「找不到对应的 wheel」 | 部署包不完整（wheel 丢失） | 用完整部署包重装 |
| `install` 报「安装目录里没有 tpops_kafka_collector/」 | 解压不全或目录层级不对 | 重新完整解压，确认 `collector.sh` 与 `tpops_kafka_collector/` 在同一层 |
| `install` 报「无法离线安装 pip」 | 目标机既没有 pip，`wheels/bootstrap/` 也不完整 | 用完整部署包重装；或先装 `python3-pip` |
| `verify` 报 `[FAIL] TPOPS_USER 未设置` | 环境变量没配，或 `.env` 不在安装目录 | 补 `/opt/tpops-collector/.env`（自检会读它，但**只读不执行**）；systemd 下要走 `EnvironmentFile=` |
| `verify` 报 `[FAIL] 状态目录不可写` | 目录是用 root 建的，服务用户写不进去 | 水位写不进去会**静默丢去重状态**。修：systemd 加 `StateDirectory=tpops` + `Environment=STATE_DIR=/var/lib/tpops`；或 `chown tpops:tpops <状态目录>` |
| 启动即退出，日志「缺少必填环境变量：XXX」，退出码 2 | 必填项没配 | 补 `TPOPS_USER` / `TPOPS_PASSWORD` / `KAFKA_BOOTSTRAP_SERVERS` |
| 启动即退出，日志「配置校验失败：…超出允许范围」，退出码 2 | 数值越界或枚举值写错 | 按 §3 表格的取值范围改（如 `CMD_CONCURRENCY` 1~10、`ALARM_LIMIT` 1~100） |
| 退出码 3，日志「装配失败」 | 端口被占用（`HEALTH_PORT`）、Kafka 客户端构造失败 | 换 `HEALTH_PORT`；检查 broker 是否可达 |
| 启动报「健康端点监听 127.0.0.1:8088 失败：Address already in use」 | 上一个采集端进程还占着端口 | ① 优雅退出最多要等 30 秒，**等它退完再重启**；② `Ctrl-Z` 挂起（SIGTSTP）的进程也算活着。查 `ss -tlunp \| grep 8088` 拿到 pid，确认后 `kill <pid>`（挂起中的先 `kill -9`） |
| **平台认证失败，日志报「TPOPS 认证失败」** | 用户名/口令错；或**累计锁号** | 平台认证失败会累计 `login_failed_attempts` 并**锁号** → **不要盲目重试**。采集端内置 60 秒静默期。处理：确认口令 → 找平台管理员解锁 → 必要时调长静默期。**手工反复 curl 试登录会加速锁号** |
| 平台接口返回 **404** | 平台接口有**两套命名空间**：`/rds/v3/…`（认证、实例列表、监控指标、告警）与 `/rds/gaussdb/v3/…`（诊断优化 + 命令中心） | 少一段前缀就是 404。采集端已按正确路径实现，**运维侧不需要**在代理/网关上改写 |
| 某类指标大面积 `null` / 没消息 | 查询窗口太短，或 `end_time` 没回退 | `METRIC_WINDOW_HOURS` 不得小于 1；`METRIC_END_LAG_MINUTES` 保持 ≥ 5 |
| 日志「监控指标空分组告警：分组码 XXX 未返回任何指标」 | 分组码写错 | 平台对写错的分组码返回 **200 + 空 series 且不报错**，只能靠这条日志发现 |
| 日志「告警历史缺口告警：…超过平台 30 天保留窗口」 | 停机时间超过平台保留期 | 平台只保留 30 天历史告警，**补不回来**。缩短停机时间；长期停机需客户另建归档 |
| 日志「第 N/M 次重试 ……」/「重试次数用尽，放弃：…」 | 命令中心单次往返 3~8 秒，实测偶发失败约 3/50 | 偶发失败会自动重试（`CMD_RETRY_ATTEMPTS`，默认 3 次，指数退避）；持续失败看是否平台限流 → 调小 `CMD_CONCURRENCY`；用尽则该命令本轮作废，不推进水位、下轮重投 |
| 日志「命令中心返回了与上一页相同的内容…」 | 平台未按 offset 分页 | 本轮停止翻页（防卡死）。数据量大时调小 `CMD_PAGE_SIZE` |
| 消息条数远多于预期（表级/库级指标） | **维度展开**：一行结果 = 一条消息 | 6000 张表 → 6000 条消息。这是设计口径，不是缺陷；确认 Kafka 侧吞吐与磁盘 |
| 投递失败，日志有 Kafka 异常 | broker 不可达 / Topic 不存在 | 投递失败**不推进水位** → 数据会重投，不会丢。**采集端不创建 Topic** —— Topic 不存在要客户先在 broker 上建好 |
| 重启后数据重复 | `STATE_DIR` 不可写，或水位文件被删 | 确认目录可写、文件没被清。客户侧按幂等键去重，重复投递不产生重复数据 |
| `/readyz` 一直 503 | TPOPS 不可达/认证失败，或调度器卡住 | 看 ERROR 日志定位是哪一路失败；命令中心往返频繁超时则看平台负载 |
| 慢 SQL 文本被截断 | 超过 `SQL_TEXT_MAX_LENGTH`（默认 512） | 截断是**显式标记**的。需要更完整文本请调大，但评估消息体膨胀与外发合规 |
